# V01 handoff: viewer lifecycle and idle drawing

V01 is based on `c6868e798a63a427d581b33b6fb66d1d8a608fb7` in `codex/perf-v01`.

## Implementation

- `src/renderer/lib/viewerSession.ts` owns one viewer resource object, the deduplicated render-frame handle, deferred build-yield frames, a monotonic load token, visibility state, registered cleanup callbacks, and the captured-resource disposer.
- `viewer.ts` keeps the existing exported adapters (`initViewer`, `loadModelWithWorker`, `loadModel`, `buildModelFromMeshes`, `notifyViewerResize`, camera/grid/wireframe controls, and `disposeViewer`). `initViewer` returns the session handle; existing callers may ignore it.
- Rendering now starts only after invalidation. OrbitControls changes invalidate a frame; damping schedules another frame only while `controls.update()` reports movement. Model/color/grid/wireframe/part selection and resize invalidate the current session. Document hiding cancels a pending visible render and return schedules one catch-up frame.
- Loads capture a session and generation token. A completion from a disposed/replaced generation cannot attach geometry or publish current-model state. Build-yield frames are session-owned and settle when the session is disposed.
- Disposal is idempotent: it invalidates load generations, cancels render/build frames, removes session listeners, disposes model and grid/helper geometry/materials, disposes controls and renderer, removes the canvas, clears the multipart strip only for the current viewer, clears the owned diagnostic model reference, and resets the resource state. The legacy `disposeViewer()` delegates to the active session.
- The optional `window.__POLYTRAY_RENDERER_PROBE.markViewerFrame()` hook runs after an actual viewer render. `markViewerDrawCalls(count)` separately receives `renderer.info.render.calls`; the frame test does not treat draw calls or a timer as frames.
- `cameraUtils.ts` and all orientation/mesh-preparation rules remain unchanged.

## Disposal and concurrency contract

The active module reference points to the current `ViewerSession`; each session keeps its own resource object. Public adapter functions resolve the active session for existing call compatibility. Every asynchronous model load captures its owner and token before waiting. The token must remain current and the owner must still be active before adding/publishing the model. Replacing or disposing a session revokes publication rights. Session cleanup callbacks run once, in reverse registration order; a cleanup failure is logged while remaining cleanup proceeds.
