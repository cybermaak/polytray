# T01 handoff: thumbnail request identity and settlement

## Changes

- Added `src/main/thumbnailIdentity.ts`. A cache key contains the canonical indexed physical/virtual path, `contentRevision`, lowercased normalized color, 128/256/512 size, and renderer version `thumbnail-renderer-v2`. The attempt ID and cache epoch are separate attempt fields.
- Main generation now requires a current indexed row, decodes cached PNGs with Electron `nativeImage`, checks exact requested dimensions, and revalidates the captured row/revision/epoch after asynchronous cache reads. In-flight promises and scheduler jobs use full identity plus epoch keys and clear only their own entries in `finally`. Pending renderer results are keyed by unique request ID, owned by the hidden thumbnail window, checked against key/epoch/current row before write, written to an attempt-specific temporary file, and renamed atomically. Timeout, renderer failure, epoch invalidation, and hidden-window close settle once.
- Background and manual thumbnail DB updates use `createFileIndexRepository(...).updateThumbnailState` with the captured file ID and content revision. Manual handlers capture before awaiting generation and return/publish only when that exact revision accepts the update. Ready events contain an absolute PNG path and identity/revision only.
- Manual revision-race, asynchronous cache-read/revision/epoch race, decoded-dimension/corrupt-cache, and same-tick epoch replacement regressions are covered in `thumbnailRequests.test.ts` and `thumbnail-lifecycle.e2e.ts`.
- Hidden-renderer request/result payloads carry request ID, cache key, epoch, content revision, and requested dimensions. The renderer resizes its canvas before generating the PNG.
- Added an explicit scheduler dedupe-key seam. T01 enqueue paths provide the full C4 key plus current epoch; legacy callers keep file-path fallback. The scheduler retains its priority/retry behavior.
- Runtime settings now normalize `thumbQuality` to the existing 128/256/512 choice. The manual preview request passes the current thumbnail color and quality.

## Coordinator integration

- Public `ThumbnailRequestData`: existing file path/extension/cache path/color plus `requestId`, `cacheKey`, `cacheEpoch`, `size`, and `contentRevision`.
- Public `ThumbnailResultData`: existing file path/cache path/success/data URL plus `requestId`, `cacheKey`, and `cacheEpoch`. Data URLs are consumed only by the main result handler and never published in ready events or file records.
- Public `ThumbnailReadyData`: `fileId`, absolute `thumbnailPath`, `identity`, and `contentRevision`.
- `RuntimeSettingsData.thumbQuality` is optional for older internal settings snapshots; normalization supplies the current default. Current manual preview requests pass the real setting.
- `advanceThumbnailCacheEpoch(path)` is the T02 invalidation hook. It settles active attempts for that canonical path; T02 still owns authoritative cache deletion/reconciliation and must call it as part of invalidation.
- PreviewPanel/App changes are limited to passing current thumbnail quality for manual requests. V03's separate `content_revision` caller change and preview registration change were preserved.
