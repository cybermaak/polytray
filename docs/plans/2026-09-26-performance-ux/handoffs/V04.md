# V04 handoff: background orientation and budgeted mesh assembly

Status: REVIEW. Candidate is on `codex/perf-v04`, based on accepted source `f707d33`. The coordinator owns tracker status. Do not mark V04 DONE until independent review/integration and the required full Product gate pass.

## Implementation

- `meshPreparation.ts` provides shared pure preparation. It computes missing vertex normals, applies the established orientation rule, and returns the orientation transform plus oriented source-coordinate bounds before viewer scale normalization.
- STL/OBJ workers and the hidden 3MF renderer prepare geometry before serialization. The compact position/normal/index format and transfer ownership remain explicit; parser geometries are disposed after serialization and sender buffers are never read after transfer.
- The hidden 3MF result carries S04 source-build measurements separately from oriented preview bounds. It uses the existing `measureFast3mfBuild` and `ModelMeasurement` contracts without changing S04 code. Known units remain verified in mm; unknown or unsupported provenance stays unavailable. The fallback 3MF E2E confirms meshes can parse while an unavailable measurement remains unavailable.
- Preview and thumbnail use `prepareModelGroup`, with a golden test comparing orientation, transformed positions, normals, and bounds. Golden tests also cover indexed/nonindexed geometry, multipart transforms, normalized normals, one-time build transforms, and source-build mm measurements versus preview-coordinate bounds.
- Visible assembly uses zero-copy attribute wrapping for meshes up to 32,768 vertices. A larger mesh is split into bounded chunks with local index remapping; each emitted chunk owns stable position/normal attribute buffers rather than views into reusable scratch. Triangle copying checks cancellation every 256 triangles and yields at 8 ms or 100,000 consumed vertices. It does not wait until the whole mesh is wrapped before yielding.
- Indexed streams larger than the bounded index-chunk capacity are also chunked even when they reference only a few unique vertices. Index item size, triangle shape, and range are validated on both zero-copy and chunked paths.
- STL/OBJ source-build measurement construction rejects nonfinite source positions or world transforms and emits explicit unavailable `invalid-geometry` provenance, using the existing measurement constructors/contracts. S04 core code remains unchanged.
- `AbortSignal` now reaches assembly and the thumbnail-strip async stages. Frame waits race against abort. A standalone abort while `isCurrent()` remains true returns no group and disposes partial geometries/materials, so the viewer cannot attach stale output. Session/load-token checks remain in place before yields, after yields, and before scene mutation.
- First-render metrics separate load-to-first-model-frame from synchronous `renderer.render` submission. `renderSubmitMs` is CPU-side submission time, not GPU completion; GPU work completes asynchronously. Hidden 3MF parse, preparation, and serialization timings are separate.
- The unused synchronous `loadModelFromUrl`/`loadModel` path remains removed after source tracing found no callers; PreviewPanel uses `loadModelWithWorker`.

## Before/after responsiveness evidence

A detached temporary checkout of the accepted `f707d33` source was built separately. Source tracing confirmed the active PreviewPanel flow called `loadModelWithWorker`, and its `buildModelFromMeshes` ran `applySmartOrientation(group)` on the visible renderer. The uncalled legacy URL loader was not used for this comparison.

Both versions used a portable 250,000-triangle binary STL and a visible-renderer `PerformanceObserver`:

| Build | Click/load to first model frame | Longest visible task through first frame | Render submission |
|---|---:|---:|---:|
| `f707d33` baseline | 224.7 ms | 51 ms | Not separately recorded |
| Candidate | 280.0 ms (observed range 280.0–507.1 ms across runs) | 0 ms | 19.9 ms |

The candidate removes the observed 51 ms visible orientation task; background preparation/chunking increases first-frame latency for this dense fixture. Measurements are local Electron/macOS observations, not cross-platform guarantees. The multipart fixture uses 32 transformed 3MF instances; latest first frame was 21.2 ms, no visible long task through first frame, and 7.5 ms renderer submission. Real-world 3MF performance was not measured.
