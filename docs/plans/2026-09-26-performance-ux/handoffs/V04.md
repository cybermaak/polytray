# V04 handoff: background orientation and budgeted mesh assembly

Status: REVIEW. Implementation candidate is on `codex/perf-v04`, based on accepted source `f707d33`. The coordinator owns tracker status. Do not mark V04 DONE until independent review/integration and the required full Product gate pass.

## Implementation

- Added `src/renderer/lib/meshPreparation.ts` as the shared pure preparation entrypoint. It computes missing vertex normals, applies the existing smart-orientation rule, and returns the orientation matrix plus pre-display-normalized bounds.
- STL/OBJ workers and the hidden 3MF renderer prepare geometry before serialization. Worker and hidden-renderer payloads retain the compact position/normal/index attributes, include orientation and bounds, and worker parser geometries are disposed after serialization. No transferred buffer is read after `postMessage`.
- Preview assembly no longer runs smart orientation or computes fallback normals in the visible renderer. It adopts transferred typed arrays, uses prepared bounds for normalization/recentering, checks the owning session/load token around frame yields and before scene mutation, and disposes partial groups if stale. Assembly yields at an 8 ms elapsed slice or 100,000 accumulated vertices.
- The unused synchronous `loadModelFromUrl`/`loadModel` viewer route was removed after source tracing found no callsites; PreviewPanel exclusively uses the worker-backed `loadModelWithWorker` route.
- Thumbnail rendering calls `prepareModelGroup`, sharing the same orientation/preparation rules with preview. The S04 shared 3MF measurement core was not changed; source measurement provenance stays on its existing contract, separate from prepared display bounds.
- Added first-render metrics separating load-to-first-render duration from synchronous `renderer.render` submission duration. GPU completion is asynchronous, so `renderSubmitMs` is not GPU completion time. Hidden-renderer parse, preparation, and serialization durations are reported as separate phases.
