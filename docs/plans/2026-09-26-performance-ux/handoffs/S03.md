# S03 metadata worker handoff

## Worker contract

`MetadataWorkerClient.extract(request, { signal })` accepts:

```ts
{
  requestId: string;
  fileId: number;
  contentRevision: number;
  filePath: string;
  extension: string;
}
```

It resolves to `MetadataSummary` only. The utility replies with `{ requestId, summary }` or `{ requestId, error }`; no model buffers or database/user-annotation data cross the boundary. `ScanServiceOptions.extractMetadata(filePath, extension, context)` receives the captured `{ id, path, contentRevision }`, a request ID, and the scan abort signal. Main applies the result synchronously with D01's expected-content-revision check.

The client starts one Electron utility process lazily, permits one active extraction and two queued requests, and applies caller backpressure beyond that. It owns readiness/request timeouts, retries an active request once after a worker exit, rejects invalid parser responses, and terminates the owned process on active cancellation or shutdown. Process listeners are removed on exit/termination; stale exit events cannot detach a newer worker.

## Parser behavior

- File-backed OBJ lines update counts and bounds without collecting or joining the file.
- Binary STL reads 50-byte triangle records incrementally and rejects truncated/mismatched binary data. ASCII STL uses a streaming line counter.
- ZIP OBJ entries stream directly; ZIP STL entries inspect and replay a bounded prefix, then stream either ASCII lines or binary records. Archive-owned streams are closed on completion and errors.
- 3MF remains on the existing buffered parser path for S04; this worker keeps that work off main.
