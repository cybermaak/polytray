# V05 handoff: progressive multipart preview images

Status: IMPLEMENTED; review and final integration acceptance pending. Candidate branch: `codex/perf-v05`, based on accepted local snapshot `e8272d7` (V04 source `19228cf`).

## Implementation

- The viewer attaches the usable model, fits the live camera, and waits for the first rendered frame before `loadModelWithWorker` resolves. PreviewPanel therefore cannot dispatch `ready` ahead of that frame.
- Removed full-viewer `toDataURL` capture and temporary part visibility/camera changes. The live renderer no longer preserves its drawing buffer.
- `PreviewParts` owns the accessible React part strip, stable placeholders, selection buttons, and an `IntersectionObserver` with a 256px horizontal margin. Only visible/near-visible cards enqueue image work.
- A single lazy 128×128 WebGL renderer, independent scene and camera render cloned part objects. The queue serializes jobs, yields between renders, caps its pending backlog and LRU cache at 64, and revokes URLs on eviction, replacement and close.
- Work is guarded by the ViewerSession load token. Replacement cancels active/pending work and disposes the thumbnail renderer; close also disposes and force-loses the viewer context. Part image rendering never changes the live camera, model visibility, or load state.
- The React image map follows the 64-entry queue LRU. Eviction/replacement first removes the URL from React state; `useLayoutEffect` acknowledges removal, then the queue revokes the object URL. The image renderer drops its Three.js renderer, scene, camera, and clone references before awaiting asynchronous canvas encoding.
