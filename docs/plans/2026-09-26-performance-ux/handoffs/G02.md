## Scope-index startup follow-up

The source trace found the cause of the blank startup interval: `startAfterRecovery` awaited all scope backfill before resolving `startupReady`, while renderer boot awaited `completeMetadataRestoreStartup` before its legacy file read. Startup now completes restore readiness first; the first `GET_LIBRARY_PAGE` still starts/joins `FileIndexRuntime.startBackfill()` through the existing `runMainMutation` readiness gate. The renderer keeps its legacy snapshot visible only when its exact unfiltered startup query still matches. Row/annotation mutations invalidate that snapshot. Active collections do not use the global legacy slice because filtering after the first page can omit members and undercount results; the toolbar shows a loading count until the correct collection page arrives.

- On a synthetic grouped 50k database with an incomplete index, the first legacy card was DOM-visible in **103.9 ms** after the search control attached, while `scope_backfill` was incomplete at cursor **9,250/50,000** (92,500 scope rows).
- `GET_FILES` returned the expected 200-row legacy page and total 50,000 in **7.1 ms** while `GET_LIBRARY_PAGE` remained pending. That first page later resolved in **1,364.3 ms** after the controlled request started.
- With the same synthetic 50k shape preseeded complete, the first card appeared in **152.6 ms** and the controlled page request took **100.1 ms**. These are single measurements, not percentiles.
- `scope-backfill-browsing.e2e.ts` holds startup backfill after a partial 600-row batch, confirms visible legacy cards and incomplete index state, reloads with a collection member inside and another beyond the first global 200-row page, verifies no partial collection cards/count while held, releases backfill, confirms both identities and a two-model collection result, then traverses all display pages and checks unique reachability.
- The test-only hold requires `POLYTRAY_SCOPE_BACKFILL_TEST_HOLD=1`, uses reached/release files under the validated isolated scratch directory, polls with an AbortSignal-aware yield, and releases during test cleanup.
- The scan-streaming E2E's isolated queue probe observed 50/50 buffered discovery events and 100/100 metadata depth, including the active extraction, across 19,702 size-change observations in two focused runs and the final full Product run. Its discovery observer is installed only when the isolated metrics flag is enabled. These maxima measure the two configured queue buffers; the separate pending indexing batch and a producer event blocked outside the discovery buffer are not included.
- The targeted E2E passed. The full Build/Product gate above passed afterward on the exact final source/test tree. Serial specification and quality review passed, including collection-membership paging and honest interim result count.
