## Measured results

- Grouped 50k production `GET_LIBRARY_PAGE`: 100.4/105.8 ms median/p95 in the worker capture and 101.5/115.0 ms in an independent integrated-primary capture. Both meet C10's <=150 ms median and <=250 ms p95.
- Cold first grouped 50k page: 1,617.9 ms request-to-response after the renderer search input was ready. The main heartbeat ran through the cold and warm series and recorded 121.74 ms maximum gap over 134 samples. This is a measured first-readiness delay, not evidence of an event-loop stall.
- 5k delayed-subtree scan: first queryable batch at 5.3 ms, first file card DOM-visible at 213.6 ms before the held subtree was released, 8 progress events with one first-batch and one total-known boundary, maximum 4 regular events in any rolling second, and 29.93 ms heartbeat maximum over 62 samples.
- Metadata worker E2E: 289 `GET_LIBRARY_PAGE` samples while the scan remained active and `metadataCompleted` remained zero before and after each query; median/p95 0.6/0.8 ms; heartbeat maximum 26.05 ms over 17 samples. This does not prove the worker was actively parsing during every query. A separate run measured one metadata completion in 392 ms and 36.04 ms maximum heartbeat over 13 samples.
- Preview preparation: one focused run observed a 107 ms multipart CPU long task; three isolated repeats and the integrated run observed 0 ms. The outlier is retained as non-reproduced. Integrated dense/multipart first frames measured 282.2/22.5 ms; render-submit measured 19.2/6.2 ms. GPU upload was not measured separately.
- Lifecycle/resource E2E passed 20 preview open/replace/close cycles with zero settled/minimized viewer frames, 20 WebGL contexts lost after cleanup, 40 visible-renderer Workers created and terminated, 2 stable BrowserWindow pages, and disk thumbnail bytes stable at 5,034. This does not count utility processes, all transferred ports/listeners, or in-memory thumbnail bytes.
