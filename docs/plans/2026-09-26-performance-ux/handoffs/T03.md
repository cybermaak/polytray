# T03 handoff: shared thumbnail image cache

Branch: `codex/perf-t03`
Base: `15eeacd` (local `main`)

## Implementation

- Added `src/renderer/lib/thumbnailImageCache.ts` with one renderer-wide image cache. It accepts only cache-path reads through `window.polytray.readThumbnail`, rejects inline `data:` values before IPC, shares in-flight reads by path plus optional primitive identity, and keeps completed data URLs in a 128-entry / 16 MiB LRU.
- Missing, malformed, and rejected reads return `null` without a permanent negative cache entry. `invalidate(path)` clears completed and in-flight keys for that path and notifies mounted consumers; global invalidation clears all keys. Old in-flight reads cannot repopulate an invalidated key.
- Added `src/renderer/components/ThumbnailImage.tsx`. It keeps one same-size `<img>` element with a transparent placeholder, defaults `alt` to empty for model cards whose nearby text supplies the name, and ignores results after unmount or request-key change. A decode error returns that image to the placeholder without triggering a retry loop.
- Consumers remain unchanged in this task. No data URL is written to `FileRecord`, SQLite, or a path-based API.

## Consumer handoff

U01 can replace the private image loaders in `FileGrid.tsx` and `ComparePanel.tsx`, plus `ArchiveThumbnailGrid` in `FileGrid.tsx`, with `ThumbnailImage`. Pass the cache path and a stable identity such as `content_revision` when available; keep the existing fixed-size wrappers/classes and use `alt=""` when adjacent card text names the model.

When a validated thumbnail-ready event arrives, U01/T02 must call `thumbnailImageCache.invalidate(thumbnailPath)` before applying the path to file state. This is required when regeneration overwrites the same path with the same identity. The T03 API does not own event validation or alter main-process read authorization.
