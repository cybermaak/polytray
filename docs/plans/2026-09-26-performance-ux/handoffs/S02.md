# S02 — streaming scan checkpoint

Status: implementation checkpoint is ready for static review. The source and unit gate pass; the isolated Electron 5k acceptance is committed but has not been run because the shared runtime lane is reserved for V03.

## Implementation

- `streamDiscoverFolder()` in `src/main/scanner.ts` yields `file`, `scope-complete`, `scope-error`, and `discovery-complete` events. Scope events carry an explicit directory/archive kind; failures and exclusions remain distinguishable. The existing `discoverFolder()` and `scanFolder()` collectors remain for compatibility.
- `ScanService` indexes as discovery proceeds. It bounds queued discovery events to one configured batch and queued metadata work to two batches, caps a repository call at its prepared 250-record limit, commits on batch size, a 50 ms elapsed window, or scope completion, and yields to the event loop after a batch. First-batch and terminal progress are immediate; intermediate progress is rate-limited to four per second. `total` remains `null` until discovery terminates.
- The service captures S01's full prune snapshot before discovery and keeps only discovered paths, scope proof, and bounded batch records rather than a second full `ScannedFile[]`. Pruning uses the new iterable-path adapter and retains the original repository guards.
- Before snapshot/discovery, each job subscribes to D01 post-commit mutations. Row changes inside its root fence queued observations; annotation-only and thumbnail-only changes do not. Scan records carry the snapshot content revision, or `0` when absent, and only repository-returned committed identities are enriched or counted as indexed. D02's absent/revision guard is included as dependency commits `7e3a68d` and `80e0a86`.
- Same-root requests coalesce; overlapping parent/child jobs serialize; unrelated roots can run concurrently. The service has an internal cancellation method that drops uncommitted scan records and queued metadata, retains starting rows, and does not prune. UI and IPC cancellation controls remain S06. Running metadata extraction is still main-process work and cannot be interrupted until S03 owns extraction workers.
- `src/main/ipc/scanning.ts` now routes the existing scan handlers through the service and continues to return/send `totalFiles`, state, affected scopes, retained/deleted counts, and the new job counters. Existing thumbnail scheduling starts after scan completion.
- Commit `1577327` separately adapts the existing scan progress UI to nullable totals, with a focused test that prevents `NaN`/`0 of 0` output. The C3 scope kind is additive and does not change event names.
