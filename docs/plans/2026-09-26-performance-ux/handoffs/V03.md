# V03 preview runtime handoff

## Process ownership and cancellation

The owned preview renderer is accepted as ready only when it has a positive,
valid OS PID distinct from the current main and thumbnail renderer PIDs. The
same guard is checked immediately before `forcefullyCrashRenderer`. When the
PID is unknown/shared, the manager refuses readiness and closes only its own
window. PID reads tolerate destroyed windows, and the closed callback uses the
sender ID captured before destruction.

The geometry response no longer passes through the main process. Main creates
the requester response channel and transfers its main-owned endpoint into the
owned preview renderer. The hidden renderer returns its prepared meshes through
preload directly to the requester, transferring the mesh `ArrayBuffer`s. Main
receives only a bounded request-ID settlement acknowledgement. After endpoint
transfer, main sends cancel/error via a small requester-control IPC; before
transfer it can use the ordinary response port. Sender/request ownership is
checked on settlement, and requester navigation/render-process exit cancels
owned work.

The isolated E2E barrier is enabled only when
`POLYTRAY_ISOLATED_TEST=1`; it targets one selected request ID and synchronously
holds that preview renderer. No general application environment or parser
behavior enables it.
