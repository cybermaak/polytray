# T02 thumbnail invalidation handoff

Status: DONE on the integrated S02/S03/T02 candidate after the 2026-09-27 combined Build/Product gate. T02 owns the main invalidation service and producer event; U01 remains responsible for consuming invalidation events in the shared renderer image cache.

## Contract and service behavior

- `invalidateThumbnails(scope, settings, getMainWindow)` accepts `{kind:"all"}`, `{kind:"folder",folderPath}`, or `{kind:"files",modelPaths}`.
- The frozen `ThumbnailInvalidatedData` contract is `{kind:"all"}` or `{kind:"paths",modelPaths,thumbnailPaths}`. The two path arrays are independent sets, each event is capped at `THUMBNAIL_INVALIDATION_PATH_BATCH_SIZE` (256) per array, and larger invalidations emit multiple events.
- Invalidation operations serialize FIFO. The service advances epochs, cancels affected active/pending work, clears row references with content-revision guards, removes only cache-directory-contained PNGs, publishes invalidation events, and requeues the requested scope.
- Cache version/missing-reference reconciliation completes before thumbnail cache paths can be read or returned through IPC. Failed deletions are logged and do not suppress invalidation publication or requeueing. Failed paths remain quarantined; old reads spanning quarantine/removal are rejected by monotonic per-path/global read epochs. Read-epoch state is retained only while reads are active. Quarantined cache misses render fresh output only while the row identity and content revision remain current.
- Manual thumbnail publication checks the captured cache epoch before any DB update or ready event. The coordinator-owned IPC adapters preserve folder-refresh's `undefined` result and clear's `true` result.
