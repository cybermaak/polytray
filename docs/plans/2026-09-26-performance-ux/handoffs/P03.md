## Scope and result

The shared backup validator now accepts JSON text or bytes and checks the 50 MiB bound before parsing. It enforces the combined 250,000 annotation limit, rejects unsupported versions, malformed records, relative paths, duplicate canonical paths within either source array, invalid collections and preferences, and defaults a missing v1 `pendingAnnotations` array to empty. Indexed and pending arrays may still overlap.

`src/shared/metadataImportPlan.ts` adds a pure plan builder. It matches canonical identities exactly, preserves archive member suffixes, keeps indexed and pending records separate, classifies matched/unmatched/changed/unchanged records, merges tags and collection membership, fills blank notes/default print status, and reports preserved note/status conflicts. Collection ID/name matches merge; ID collisions with a different name receive deterministic remap IDs for the same input/current state. Settings and roots default to replacement disabled and include normalized before/after values. No apply function, IPC, file write, database mutation, settings mutation, scan, or watcher action was added.

### Revision contract requiring coordinator decision

The current pure-plan API captures `databaseBrowseRevision`, `databaseAnnotationRevision`, and `rendererRevision`; `isMetadataImportPlanCurrent` compares all three. D01's actual repository currently provides browse, stats, and topology revisions, with no separate annotation revision counter. Browse revision advances when annotation changes, so this API must be reconciled before a main-process P04 consumer is wired. Do not pass a made-up annotation revision or add a database counter without coordinator approval. Recommended resolution is to use the real browse revision plus renderer revision, unless the coordinator approves a distinct annotation revision producer. This handoff intentionally leaves that decision outstanding.
