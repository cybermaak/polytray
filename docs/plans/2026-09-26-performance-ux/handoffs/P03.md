## Scope and result

The shared backup validator now accepts JSON text or bytes and checks the 50 MiB bound before parsing. It enforces the combined 250,000 annotation limit, rejects unsupported versions, malformed records, relative paths, duplicate canonical paths within either source array, invalid collections and preferences, and defaults a missing v1 `pendingAnnotations` array to empty. Indexed and pending arrays may still overlap.

`src/shared/metadataImportPlan.ts` adds a pure plan builder using the existing public `MetadataImportPlan` from `backupContracts.ts`; it does not define a competing public plan shape. Each canonical identity has one effective update. The target is indexed when that identity exists in the complete indexed snapshot, otherwise pending. Merge order is the existing target, incoming `annotations`, then incoming `pendingAnnotations`. Disjoint tags union; existing nonempty notes/nondefault status win conflicts. A pending plan is a set of upserts and never represents replacement/deletion of unrelated pending rows. Source provenance is retained on each update.

The input revision is a Node built-in SHA-256 digest of the validated backup and caller-supplied current snapshot. Nonblank notes remain text-identical through backup serialization/validation and annotation merging; trim is used only to classify whitespace-only notes as blank. A merge that only adds a tag preserves existing multiline indentation and trailing newlines. Collection ID/name matches union members. ID collisions with a different name receive deterministic remap IDs; occupied remap candidates get monotonic numeric suffixes, and retries reuse an existing remapped collection with the same name and union its members. Collection lookup uses an ID map. Collection order follows the current normalized order, with imported collections appended. Settings before/after are complete normalized current settings including operational settings and existing local-only/future fields such as slicer configuration and panel widths. Optional import replacement overlays only allowlisted portable backup keys; roots/settings replacements default off. No apply function, IPC, file write, database mutation, settings mutation, scan, or watcher action was added.

### Revision contract

The plan captures D01's real `browseRevision` and the renderer revision. `isMetadataImportPlanCurrent` compares those two values. Do not supply a fabricated annotation revision. P04 must advance the same durable browse revision in its transaction whenever it mutates pending annotations, so a preview becomes stale after any competing indexed or pending annotation edit. The pure planner input's `annotations` must include every indexed file row, including rows with empty tags, notes, and print status; page-limited or “annotated rows only” snapshots are invalid inputs.
