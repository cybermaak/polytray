## Change

Discovery now returns scanned files plus per-directory and per-ZIP coverage, structured errors, and a terminal state. `scanFolder()` remains as a compatibility wrapper for callers that only need the file list. A read, stat, or archive error is recorded as an incomplete scope; a pre-cancelled or mid-discovery cancellation produces no complete scope for the interrupted namespace.

The scan handler snapshots contained rows before discovery. It asks `scanCoverage.ts` which starting rows are absent from successfully enumerated scopes and deletes only rows that still match their captured row ID, indexed time, modified time, size, tags, notes, and print status. Row ID prevents same-path delete/recreate ABA; annotation comparisons preserve user edits made during discovery. Failed subtrees and corrupt ZIPs override wider successful parent coverage. Completed scans preserve the existing `totalFiles` payload field and add optional terminal information (`state`, `affectedScopes`, `retainedCount`).
