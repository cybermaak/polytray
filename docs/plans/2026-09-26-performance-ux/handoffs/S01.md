## Change

Discovery now returns scanned files plus per-directory and per-ZIP coverage, structured errors, and a terminal state. `scanFolder()` remains as a compatibility wrapper for callers that only need the file list. A read, stat, or archive error is recorded as an incomplete scope; a pre-cancelled or mid-discovery cancellation produces no complete scope for the interrupted namespace. Abort is checked immediately after each awaited directory read, model stat, ZIP open/stat, and before marking scopes complete. The existing `tests/fixtures` traversal exclusion is represented as `excluded` coverage, makes the scan partial, and protects prior rows below it from pruning.

The scan handler snapshots contained rows before discovery and passes that snapshot to `scanPruner.ts`; the production prune function applies the pure coverage decision and a final guarded SQLite `DELETE`. It deletes only rows that still match their captured row ID, indexed time, modified time, size, tags, notes, and print status. Row ID prevents same-path delete/recreate ABA; annotation comparisons preserve user edits made during discovery. Failed and excluded subtrees and corrupt ZIPs override wider successful parent coverage. Completed scans preserve the existing `totalFiles` payload field and add optional terminal information (`state`, `affectedScopes`, `retainedCount`).

The prune service indexes snapshot rows by ID once before deleting, keeping large prune passes linear in the snapshot and candidate counts.
