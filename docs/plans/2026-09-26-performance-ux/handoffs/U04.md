# U04 handoff: keyboard navigation and focus

## Implementation

- Added stable-key roving focus to the virtualized file grid. Arrow keys use rendered CSS column count; Home/End use the loaded range; PageUp/PageDown use the visible page. `VirtuosoGrid.scrollToIndex` and a bounded render/focus retry move focus to unmounted cards.
- Vertical page-edge requests preserve the requested column and focus the matching stable key after the next page arrives. Refreshes retain focus by key, fall back to the nearest surviving item after removal, and ignore metadata-only refreshes when the key sequence is unchanged. Pure page appends preserve scroll instead of scrolling back to the prior roving item. When that logical key is virtualized out of the DOM, the first rendered card temporarily provides the grid tab stop without replacing the logical key.
- Regular files support Enter to preview, Space to preview outside multi-select, and Space to toggle selection in multi-select. Archive summary cards have no selection control and remain preview/navigation targets. Existing modifier-click and drag handling was left intact.
- Added named card/selection controls, pressed/selected/current states, visible keyboard outlines, and coalesced result/selection status announcements. Each card's selection button remains pointer-operable but is excluded from sequential Tab stops. `Shift+Enter` toggles the focused file to start batch selection; after a selection exists, Space toggles the focused file. Ordinary Enter and Space preview when multi-select is inactive. The grid description documents this path.
- Folder navigation now exposes a named tree with roving focus, Up/Down/Home/End movement, Left collapse/parent movement, Right expansion/child movement, and selected/expanded states. Nested treeitems are inside `role=group`. `data-folder-path` is present on both the treeitem and `.library-folder-item` row for existing app E2E consumers. Library root removal stays available by pointer through the existing control and by Delete on the focused root treeitem; the hint and `aria-keyshortcuts` document the action, and the control is not an extra Tab stop. Sidebar Add Folder, theme, and Settings buttons remain independently keyboard reachable. Focus remains on a selected nested folder.
- Closing compare restores focus to its invoking control. If a selected item has been virtualized out, the rendered grid fallback provides an available tab stop while preserving the logical focus key.
- Added a shared topmost overlay focus manager. Settings and narrow/expanded preview contain Tab focus, consume Escape only when topmost, and restore focus to their invoking element when available. Docked preview stays nonmodal. PreviewPanel already exposed `onClose`; App records/restores the invoking element without changing the callback API or preview geometry/state behavior.

## Post-V05 quality follow-up (2026-09-28)

- A quality review found that restoring the overlay's opening scroll position on close would undo a user's scroll made while the overlay remained open. Added a responsive E2E that first preserves the exact no-scroll open/close position, then scrolls the exposed grid with the overlay open and requires close to retain that latest position. The regression failed on the opening-snapshot implementation (7411.5 restored instead of the close-time 7491.5).
- Preview close now captures the current grid scroller position at close time and restores that value in the preview-close layout commit. Focus restoration continues to use `focus({ preventScroll: true })`; overlay mode still permits grid scrolling.
- `npm run build` passed. Focused keyboard and responsive E2Es passed **4/4**, including the new wheel-scroll regression and the prior tree focus and exact no-scroll cases. Final `PYTHON=/usr/bin/python3 npm run test:product` passed with **383 unit passes, 1 Windows-only skip; 51 E2E passes, 1 optional real-model skip**. The generated test bundle was restored to SHA256 `6ca9f75c11d9330221860ade9fdb641cac6728a9f0a4cc1883989506a39fc109`.
- A follow-up review caught the overlay focus cleanup's later raw `focus()` call. The responsive E2E now scrolls the exposed grid until the still-mounted invoking card is offscreen, verifies focus returns to it, and checks exact scroll preservation. Instrumentation made the missing cleanup option RED (`preventScroll` was `null`); cleanup now uses `focus({ preventScroll: true })`. The focus-first path remains unchanged: it still focuses the first available control or the container fallback.
- The expanded-folder focus assertion also reproduced `document.activeElement === body` while the expanded treeitem retained `tabindex=0`. Inspection traced stale pending grid `focusItem` retries after focus left the grid. `FileGrid` now invalidates those retries for actual external focus targets, while preserving pending work through browser `body`/document-element fallback during virtualization. The tree's post-expansion recovery restores focus if it escaped the tree. The ArrowRight test keeps strict expanded, roving-tabindex, and active-element assertions.
- A page-edge trace showed the integrated mismatch came from the test reading the active item before `End` finished its asynchronous virtualized focus: its `not.toBe(initialKey)` could pass on the prior ArrowDown, yielding stale `file:524` while the settled boundary target was `file:571`. The regression now starts at the archive summary, waits for End to focus the last key in the loaded page, verifies the summary unmounted, preserves the dynamic ArrowDown key assertion, and checks a real Shift+Tab exit remains outside the grid. A separate Product attempt exposed that body fallback could cancel this pending End focus; ignoring only body/document-element fallback fixed it while real external focus still cancels stale retries.
- Final verification on this follow-up: `npm run build` passed; focused keyboard and responsive E2Es passed **4/4**; `PYTHON=/usr/bin/python3 npm run test:product` passed with **383 unit passes, 1 Windows-only skip; 51 E2E passes, 1 optional real-model skip**. The generated test bundle was restored to SHA256 `6ca9f75c11d9330221860ade9fdb641cac6728a9f0a4cc1883989506a39fc109`. No assertions or timeouts were weakened.
