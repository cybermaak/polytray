# F01 handoff: contracts and preview seams

F01 is based on `3d95fd39ae81f20ff989d6bb1ce3bbc2162093a5`. It freezes the approved C1-C9 domain contracts while retaining existing payload shapes and behavior until their implementing tasks land.

## Ownership and wiring

- `src/shared/{libraryQuery,backgroundJobs,thumbnailContracts,previewContracts,measurementContracts,backupContracts}.ts` declare shared contracts; `src/shared/types.ts` re-exports them. No settings or collection store was introduced.
- `src/main/previewParseService.ts` owns the extracted 3MF broker helper and injectable preview-window lookup. Current registration remains called by `initThumbnailService` in `src/main/thumbnails.ts`; the future coordinator may own registration when it is integrated.
- `src/preload/previewBridge.ts` owns preview request and MessagePort registries/listeners. `src/preload/index.ts` constructs it once and exposes its methods through the existing API.
- `src/renderer/lib/previewParseRenderer.ts` owns hidden-renderer preview request handling and mesh serialization. `thumbnailRenderer.ts` invokes it during existing hidden-renderer initialization and retains thumbnail rendering.
- The new main/preload/renderer preview seam files transfer to V ownership after integration. F01's contract modules are shared foundations for downstream task owners.

## Exact migration reservations

- D01 owns SQLite migration 5 for `content_revision`, `archive_path`, file scope membership/indexes, browse revision state, and bounded backfill. F01 does not edit the schema or add fields to existing `FileRecord` payloads.
- D owns the schema edit for migration 6 requested by P04 for metadata-backup import journaling/transaction markers. P04 owns import persistence/recovery behavior. F01 does not implement backup persistence or import behavior.
- T01 owns runtime quality and required-field changes, including the later thumbnail-path contract enforcement. F01 leaves current runtime payload behavior unchanged.
- V03 owns request cancellation, request binding, and the dedicated lazy hidden preview window. F01 does not change the current thumbnail-window runtime strategy.

## Consumer wiring points

- `LibraryQueryClient` is consumed by U01's paged browse/query path and V02 archive preview navigation. Existing `getFiles` IPC remains until callers migrate.
- `IndexRepository` is implemented by D01 and becomes the shared write path for scan, watcher, metadata, and committed mutation notifications. `IndexInput` allows new files without database IDs; batch results return committed IDs and content revisions. Enrichment, annotation writes, and prune candidates carry expected revisions/generations.
- `ScanJobs` is implemented by S06. Thumbnail controls and the `ThumbnailJobs` adapter are implemented by T04. Both are exposed over IPC only with real handlers.
- `PreparedPreview`, the renderer strategy client, the IPC transport client, and cancellation types are wired by V03 and the preview strategy/viewer work. AbortSignal stays in the strategy layer; IPC cancellation uses request IDs. Current `requestPreviewParse(filePath, ext): Promise<SerializedMesh[]>` stays intact.
- Measurement declarations are populated by S04 and formatted by its UI consumers. Backup export accepts a normalized renderer snapshot and returns typed outcome/counts; import preview accepts the full normalized current renderer snapshot and includes revisions and plan counts, while commit stages renderer state for acknowledgment/reconciliation. Startup reconciliation can discover pending recovery without a transaction ID and returns typed none/abort/roll-forward/blocked outcomes. P04 owns persistence/recovery. Slicer declarations are implemented by its handoff task.
