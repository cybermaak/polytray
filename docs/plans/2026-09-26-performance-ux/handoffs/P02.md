## Format decisions

The version-1 JSON document contains `format`, `version`, `exportedAt`, `appVersion`, `annotations`, `pendingAnnotations`, `collections`, `libraryRoots`, `preferences`, and a `manifest`. The manifest states that the backup is metadata-only and source model files are not included. The required `pendingAnnotations` array is separate from indexed `annotations`; each is unique by canonical path. An indexed annotation and a pending annotation may share a path, preserving different notes/status without export-time merging. Duplicate records within one source union normalized tags only when their notes and statuses agree; conflicting duplicate notes/statuses fail explicitly.

Physical paths must be absolute. Native paths are normalized for this host; foreign Windows drive/UNC and POSIX absolute paths are normalized in their own path dialect and remain foreign identities. Ambiguous relative paths fail instead of being anchored to this process's working directory. For an archive-backed path, only the physical archive path is canonicalized; the encoded member suffix is copied verbatim. ZIP names such as `a/../Parts/Model.stl` and `Parts/Model.stl`, and names that differ by case, therefore remain distinct. Roots and collection members are canonicalized and deduplicated. Collections and roots come from the caller's normalized renderer snapshot; no page query or second state store is introduced. Preferences use the existing settings normalizer, but only explicitly supplied portable fields are emitted. Operational scan timings, page size, cache paths, model metadata/bytes, SQLite IDs, and executable settings are omitted.

## Implementation and evidence

The main service reads annotation rows and calls the pending provider in one synchronous SQLite transaction before opening the save dialog, with no SQLite transaction held across an await. The provider receives that DB connection for any DB-backed pending rows. Both sources are copied and normalized into the export document before the first await, so a mutable pending source cannot change the chosen snapshot while the native dialog is open. The revision provider is checked before dialog preparation, after the dialog resolves, and immediately before atomic rename. Pending records arrive through an explicit optional provider; P04 owns their persistence/source.

The default writer creates a mode-0600 temporary file in the chosen target directory, writes and syncs it, checks the renderer revision, then renames it over the target. Cancellation does not write. Errors clean up the temporary file and leave the previous target in place. The service reports location plus indexed annotation, collection, and pending annotation counts. The serializer writes an already-built document directly; validation stays explicit in the main export service and the pure untrusted-document validator, avoiding a second full normalization pass.

Red-to-green regressions were added for unsupported/malformed input, archive paths (including distinct `a/../` and regular entries), foreign absolute and relative paths, overlapping indexed/pending records, Unicode notes, all 510 indexed rows (including collection membership for row 510), portable-field exclusion, native dialog cancellation, renderer revision changes while the dialog is open and before rename, mutable pending data changed during the dialog, write failure, and export-only IPC runtime validation. The pending provider test confirms it runs inside the annotation read transaction and verifies the export keeps the original point-in-time values. SQLite fixtures use in-process `better-sqlite3`; tests use temporary directories and injected dialogs/writers.

## Wiring request

Coordinator should:

1. Add `EXPORT_METADATA_BACKUP: "export-metadata-backup"` to the centralized `IPC` object in `src/shared/types.ts`.
2. Call `registerMetadataBackupHandlers({ ipcMain, db: getDb(), dialog, appVersion: app.getVersion(), getCurrentRendererRevision, getPendingAnnotations })` from the existing main registration path. The pending provider receives the DB connection and runs synchronously inside the indexed annotation snapshot transaction.
3. Expose only `exportMetadataBackup(snapshot: MetadataBackupSnapshot)` in preload, invoking that channel and returning `MetadataBackupExportResult`. Do not expose import/restore methods in this task.
4. Supply a live renderer revision check that U06 can advance when renderer-owned roots, collections, or portable preferences change; do not implement it as a constant or as only the revision from the initiating export call. P04 supplies the pending annotation provider when available.

The dedicated registration function is in `src/main/ipc/metadataBackup.ts`; it registers only the export channel and forwards the payload to the main export service, which performs runtime snapshot validation before database/dialog/file I/O. Import validation must accept a missing `pendingAnnotations` array as empty for older v1 files and validate combined annotation limits, as requested for P03.
