## Implemented

- Migration 5 adds `content_revision`, nullable `archive_path`, `scan_generation`, unique scope membership, durable content/browse/stats/topology revisions, and restartable scope-backfill cursor state. Existing simple sort indexes are replaced by `(sort key, id)` indexes; name uses `NOCASE`.
- `enumerateFileScopes` derives canonical native ancestors and physical/archive virtual ancestors. Scope membership is for browsing only; it does not grant filesystem read access.
- Scope canonicalization resolves POSIX dot segments in ZIP member paths. Native Windows keys fold case, while archive-header equality retains `isPathContained`'s resolved, case-sensitive header comparison and ZIP member names remain case sensitive.
- `backfillFileScopes(db, batchSize)` commits one bounded page and its cursor together. `isScopeBackfillComplete(db)` reports the reader-switch gate. New repository writes maintain scopes while the old browse path remains available.
- `createFileIndexRepository(db, onMutation?)` returns one prepared repository per database handle; repeated calls share it and dedupe the same callback. `subscribeToFileIndexMutations(db, observer)` offers removable shared subscriptions. Both legacy wrappers and the public repository use the same subscriber set. A legacy scan coalesces its row write and enrichment into one post-commit notification. The repository implements batched indexing, watcher add/change/remove, contained pruning, revision-guarded metadata and annotation updates, and revision-guarded thumbnail state. Thumbnail-only updates leave browse revision unchanged.
- Content identities come from a persistent globally increasing sequence. This prevents an old scan prune candidate from matching a same-path file recreated with identical timestamp and size.
- Legacy `applyScannedFileRecord` and `applyWatchedFileRecord` remain exported, but now route through one `WeakMap`-cached prepared repository per database handle. Scan records preserve the prior merge rule for older timestamps and keep the scan generation untouched; watcher records act as explicit content-change events and can refresh metrics/thumbnail state in the same transaction. Both wrappers now maintain revision identity and scope rows.

## API adapters requested

Create or subscribe to the cached repository alongside the initialized database in `src/main/index.ts`, then pass it to the owning services. Register the mutation observer before any compatibility wrapper can write; `subscribeToFileIndexMutations(db, observer)` returns an unsubscribe function, while `createFileIndexRepository(db, observer)` also registers a deduplicated callback. Legacy wrappers retrieve the same cached repository, so startup wiring receives their commits without a second set of prepared statements. Keep the existing browse reader active until `isScopeBackfillComplete(db)` is true. Call `backfillFileScopes(db, 250)` repeatedly from a startup task that yields between pages; migration itself does not scan or block on every file.

For `src/main/ipc/scanning.ts`, the compatibility wrapper now keeps current scans correct while the service moves to batched calls. Map each committed scan record to `IndexInput` (`mtime` to `modifiedAt`; parse archive identity with `parseArchiveEntryPath`) and call `applyIndexBatch({scanGeneration, records})` in bounded units. Capture `expectedContentRevision` for scan work that can outlive a watcher update. Use each returned `{id, path, contentRevision}` to guard later parser results through `applyMetadataResult`. Build prune candidates from the scan-start row identities and call `deleteContainedFiles(rootPath, candidates)` only for affirmatively completed scopes. A stale or unavailable scan must not prune.

For `src/main/watcher.ts`, map add/change events to `applyWatchUpdate`. Content-change events advance identity even when timestamp and size repeat. For removal, provide the revision associated with the indexed row as `expectedContentRevision`; the repository rejects stale removals. Do not write the `files` table directly.

For annotation editing in `src/main/ipc/files.ts`, call `updateFileMetadata({fileId, expectedContentRevision, tags, notes})`; this leaves `print_status` intact. The shared `FileRecord` declaration should add `content_revision: number` and `archive_path: string | null` once, under coordinator ownership.

For thumbnail cache publication/clearing in `src/main/thumbnails.ts` and `src/main/ipc/thumbnails.ts`, call `updateThumbnailState({fileId, expectedContentRevision, thumbnailPath, thumbnailFailed})`. It accepts cache paths or null, rejects stale content revisions, and emits a `thumbnailOnly` post-commit event.

For explicit library-folder removal in `src/main/ipc/library.ts`, snapshot the affected row identities and use `deleteContainedFiles` so scope cleanup and row deletion share the repository transaction. Preserve the explicitly destructive semantics of this user action.

The API definitions live in `src/shared/libraryQuery.ts`; D01 implements that interface in `src/main/fileIndexing.ts` and adds the thumbnail-state method for T's write path. The `WatchUpdate.remove` contract requires the caller to supply the row's expected content revision.
