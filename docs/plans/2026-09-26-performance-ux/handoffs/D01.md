## Implemented

- Migration 5 adds `content_revision`, nullable `archive_path`, `scan_generation`, unique scope membership, durable content/browse/stats/topology revisions, and restartable scope-backfill cursor state. Existing simple sort indexes are replaced by `(sort key, id)` indexes; name uses `NOCASE`.
- `enumerateFileScopes` derives canonical native ancestors and physical/archive virtual ancestors. Scope membership is for browsing only; it does not grant filesystem read access.
- Scope canonicalization resolves POSIX dot segments in ZIP member paths. Native Windows keys fold case, while archive-header equality retains `isPathContained`'s resolved, case-sensitive header comparison and ZIP member names remain case sensitive.
- `backfillFileScopes(db, batchSize)` commits one bounded page and its cursor together. `isScopeBackfillComplete(db)` reports the reader-switch gate. New repository writes maintain scopes while the old browse path remains available.
- `createFileIndexRepository(db, onMutation?)` returns one prepared repository per database handle; repeated calls share it and dedupe the same callback. `subscribeToFileIndexMutations(db, observer)` offers removable shared subscriptions. Both legacy wrappers and the public repository use the same subscriber set. A legacy scan coalesces its row write and enrichment into one post-commit notification. The repository implements batched indexing, watcher add/change/remove, contained pruning, revision-guarded metadata and annotation updates, and revision-guarded thumbnail state. Thumbnail-only updates leave browse revision unchanged.
- `createFileIndexRuntime` subscribes before writes, resumes scope backfill in bounded pages with event-loop yields, reports progress/failure, keeps scope-reader use gated until the persisted completion bit is true, and disposes its observer and pending yield. `createLibraryMutationPublisher` sends the first mutation immediately, coalesces subsequent updates at no more than four per second, preserves `thumbnailOnly` only when every merged event is thumbnail-only, and supports terminal flush/disposal.
- S01 pruning now snapshots content revision and scan generation in addition to ID/path/index time/mtime/size/tags/notes/print status. The repository performs the full predicate in the atomic `DELETE`, removes scope membership in the same transaction, and advances durable browse/stats/topology revisions. Late chunk failures publish only earlier committed chunks.
- Content identities come from a persistent globally increasing sequence. This prevents an old scan prune candidate from matching a same-path file recreated with identical timestamp and size.
- Legacy `applyScannedFileRecord` and `applyWatchedFileRecord` remain exported, but now route through one `WeakMap`-cached prepared repository per database handle. Scan records preserve the prior merge rule for older timestamps and keep the scan generation untouched; watcher records act as explicit content-change events and can refresh metrics/thumbnail state in the same transaction. Both wrappers now maintain revision identity and scope rows.

## Runtime and owning adapters

`src/main/index.ts` remains V01/coordinator-owned. After that work lands, add imports for `createFileIndexRuntime` and `createLibraryMutationPublisher`, then add the following module-level owners and startup/disposal lines. `IPC.LIBRARY_CHANGED` is the coordinator-owned new event channel; this D01 branch does not alter IPC/preload/shared declarations.

```ts
import { createFileIndexRuntime, type FileIndexRuntime } from './fileIndexRuntime';
import { createLibraryMutationPublisher, type LibraryMutationPublisher } from './libraryMutationPublisher';

let fileIndexRuntime: FileIndexRuntime | undefined;
let libraryMutationPublisher: LibraryMutationPublisher | undefined;

// Inside app.whenReady(), immediately after initDatabase() and before IPC handlers:
libraryMutationPublisher = createLibraryMutationPublisher({
  send: (mutation) => {
    if (mainWindow) mainWindow.webContents.send(IPC.LIBRARY_CHANGED, mutation);
  },
});
fileIndexRuntime = createFileIndexRuntime(getDb(), {
  onMutation: (mutation) => libraryMutationPublisher?.publish(mutation),
  onProgress: (progress) => log.info('[FileIndex] scope backfill', progress),
});
void fileIndexRuntime.startBackfill().catch((error) => log.error('[FileIndex] scope backfill failed', error));

// Register once during startup:
app.once('will-quit', () => {
  void fileIndexRuntime?.dispose(); // Unsubscribes/aborts synchronously before its promise settles.
  libraryMutationPublisher?.flush();
  libraryMutationPublisher?.dispose();
});
```

The current browse reader stays active until `fileIndexRuntime.canUseScopeReader()` becomes true. The backfill cursor is persistent, each page is bounded, and writes through the legacy wrappers already create their scope rows while backfill runs.

`src/main/ipc/scanning.ts` still uses the compatible scan wrapper until S05 migrates indexing to bounded batches. S01's production prune path now uses the repository guard and durable revisions; it prunes only affirmatively complete scopes. When migrating to batch indexing, capture `expectedContentRevision` for scan work that can outlive watcher updates, use returned `{id, path, contentRevision}` identities for `applyMetadataResult`, and build prune candidates from scan-start identities. A stale or unavailable scan must not prune.

`src/main/watcher.ts` unlink now reads the cached repository identity and calls `applyWatchUpdate({kind:'remove', path, expectedContentRevision})`; stale removals are rejected and scope cleanup/revisions publish after commit. Add/change still uses the compatibility wrapper so S05 can own its existing parse/thumbnail ordering.

Annotation editing in `src/main/ipc/files.ts` now calls revision-guarded `updateFileMetadata({fileId, expectedContentRevision, tags, notes})` and retries a bounded number of times if a concurrent content revision wins. It preserves `print_status`; the shared `FileRecord` declaration should add `content_revision: number` and `archive_path: string | null` once, under coordinator ownership.

For thumbnail cache publication/clearing in `src/main/thumbnails.ts` and `src/main/ipc/thumbnails.ts`, call `updateThumbnailState({fileId, expectedContentRevision, thumbnailPath, thumbnailFailed})`. It accepts cache paths or null, rejects stale content revisions, and emits a `thumbnailOnly` post-commit event.

Explicit library-folder removal in `src/main/ipc/library.ts` snapshots all canonically contained row identities and calls `deleteContainedFiles`; the existing handler still returns `true` and the action still deletes indexed rows. Revision guards protect a concurrent content replacement, and each bounded deletion transaction cleans its scope rows and advances durable revisions.

The API definitions live in `src/shared/libraryQuery.ts`; D01 implements that interface in `src/main/fileIndexing.ts` and adds `updateThumbnailState` for T's write path. The `WatchUpdate.remove` contract requires the caller to supply the row's expected content revision. Thumbnail SQL writes still owned by T01/T02 are in `src/main/thumbnails.ts`, `src/main/ipc/thumbnails.ts`, and thumbnail-clear paths in `src/main/ipc/scanning.ts`; they are intentionally pending and must use `updateThumbnailState` without changing browse revision.
