## Review corrections

The initial implementation (commit `2c0d865`) needed additional work before integration:

- It only checked indexed presence before preparation. The service now captures file ID, content revision, path, and extension, then checks all four again immediately before launch. Tests pause after ZIP preparation and simulate removal, replacement ID/revision, path replacement, and extension replacement; stale output is removed and the launcher is not called.
- `stat()` followed symlinks, and the original ZIP reader reopened by path. Regular sources now require a regular leaf, are opened with `O_NOFOLLOW` where available, and are compared by device/inode. ZIP reading uses an open file handle through `unzipper.Open.custom`; archive identity is checked again after extraction and before launch. Replacing an archive with a symlink fails without reading or modifying its target.
- Exclusive output ownership was previously marked before the write stream successfully opened. Ownership is now set only on the successful `open` event. A forced `EEXIST` collision test confirms the pre-existing file is preserved. Owned partial files are closed and removed after pre-cancel, cancellation after output open, and mid-stream cancellation.
- IPC requests are bounded and validated. Open and picker handlers accept only the current main window's main frame. Cancellation is scoped to that sender plus request ID; destroyed WebContents and app shutdown abort owned requests.
- Sender lifecycle listeners are registered only while that sender has active requests and are removed when the last request settles. Main-frame navigations (excluding in-page/hash navigation), renderer-process loss, WebContents destruction, and app shutdown cancel active work. Registry cleanup uses a captured sender ID and remains safe after WebContents destruction.
- The platform launcher repeats asynchronous executable/bundle validation and then runs a synchronous final guard for cancellation, indexed identity, and source inode immediately before starting a process or calling the system-default opener. A barrier test changes cancellation/revision during that validation and proves no launch occurs and extracted output is removed.
- Startup now installs `activate` and `will-quit` handlers before it starts stale-file cleanup, then runs cleanup in the background without awaiting it in `whenReady`. Cleanup catches per-file and directory errors, continues through remaining owned files, and returns counts with at most three bounded error samples for one warning. A held/rejecting cleanup test proves startup and shutdown hooks remain usable while cleanup is pending or fails.
- A missing handoff directory on fresh installs is a clean no-op; other directory/read/delete errors remain reported. The focused cleanup tests cover both cases.
- Handoff service creation moved from module import to IPC registration, after portable user-data setup. Startup cleanup only considers regular files directly inside the app-owned handoff directory and skips an unsafe directory symlink.
- macOS launch now opens the document through LaunchServices using `open -a <application> -- <model>`, so a running app receives a document-open request. The launcher waits for `open` to exit and reports a nonzero result as failure. Windows and Linux pass the model as one separate argument with `shell: false`; Linux additionally requires a regular executable file.
- The picker uses executable filtering on Windows. On macOS it selects `.app` packages as files using `openFile` without `treatPackageAsDirectory`; Electron documents that `treatPackageAsDirectory` treats packages such as `.app` as directories instead of files ([Electron dialog API](https://www.electronjs.org/docs/latest/api/dialog)). The explicit system-default option is only used when that normalized setting is selected; an unset configuration does not guess an application.

## Shared contract and U06 boundary

Renderer settings own one `slicerConfiguration` value:

- Explicit application: `{ applicationPath: string, useSystemDefault: false }`
- Explicit system default: `{ applicationPath: null, useSystemDefault: true }`
- Unset: `null`

The main process normalizes this value against the current platform before any launch. Metadata backup export/import intentionally excludes `slicerConfiguration`.

U06 supplies the selected indexed record and current normalized setting to `openInSlicer`:

```ts
{
  requestId: string,          // unique, 1-128 safe characters
  fileId: number,
  path: string,                // exact indexed identity; archive form keeps ::entry:: member opaque
  extension: string,           // stl | obj | 3mf
  contentRevision: number,
  configuration: SlicerConfiguration | null
}
```

The preload surface is `openInSlicer(request)`, `cancelSlicerHandoff(requestId)`, and `pickSlicerApplication()`. The native picker returns a selected `SlicerConfiguration` or `null` on cancellation. Results use the shared contract: `launched` with `handoffPath`, `cancelled`, or `failed` with a typed code and user-facing message. U06 owns preparing UI, explicit activation, and prevention of duplicate UI actions; it should create a request ID per action and pass that same ID for cancellation.

## Source and launch evidence

- Model and archive inputs must be current indexed rows. Their exact ID, revision, path, and extension are rechecked immediately before launch.
- Archive members are matched by their exact stored ZIP name. Absolute names, dot segments, symlinks, directories, mismatched extensions, corrupt ZIPs, and entries over 1 GiB are rejected. Streaming also counts actual uncompressed bytes, including when the ZIP header understates the size.
- Archive output uses a generated UUID filename with the model extension, exclusive creation, and the app-owned `userData/slicer-handoff` directory. Successful outputs remain for the receiving slicer; startup cleanup removes only regular files older than 24 hours in that directory. Source bytes are never modified.
- Tests mock all launch/process/dialog adapters. They cover argument boundaries with spaces, quotes, leading dashes, and Unicode; macOS launcher exit errors; Windows/Linux argv shape; platform picker options; and request ownership. No test starts a slicer or uses a user's model library.
- The macOS `/usr/bin/open(1)` manual was inspected on the implementation host. The documented `-a` selection and file-opening behavior informed the argument array. Already-running application delivery is specified by LaunchServices; no real slicer was started to smoke-test it.
