The access repair first failed its symlink regressions, then passed. Independent specification review caught a validation/open race; `localFileProtocol.ts:39-78` now opens regular files with `O_NOFOLLOW` where available and checks device/inode identity. `index.ts:578-595` serves the permitted descriptor as a stream, `thumbnails.ts:198-206` reads the checked cache file, and `ipc/files.ts:52-63,187-205` uses descriptor reads. `archiveRead.ts` retains one descriptor for ZIP ranges; `previewParseService.ts:169-211` closes it after entry extraction. Independent quality review then found short-read corruption and an abort-time source-stream error. Red/green regressions drove byte-accurate range advancement, source-stream settlement before close, and prompt `FILE_ENDED` rejection for a truncated member. The final independent quality re-review passed this bounded repair.

**Remaining path race:** This repair does not claim hostile concurrent filesystem replacement of a *parent directory* is contained. A process that can rename a validated cache or library subdirectory and replace it with a symlink before the descriptor open can redirect the path; the later fresh `lstat`/open pair can agree on the outside file. Eliminating that race requires pinning the validated directory chain or binding an earlier filesystem identity to the opened descriptor across every read path. It was not covered by the existing indexed-path contract or this narrow repair. [Node's filesystem documentation](https://nodejs.org/api/fs.html#fsconstants) lists `O_NOFOLLOW` outside the flags available on Windows; the before/open device-inode check detects different-file final-component swaps, but literal atomic symlink refusal is not proven. Treat these as explicit security hardening residuals, not as a passing symlink-race test.
